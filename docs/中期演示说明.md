# 中期演示说明

对应中期录屏里从索引到四次提问的指令。评价维度来自选题 1：Agent 要能记住整台 PC 的文件结构，并回答跨文件、跨时间的问题，而不是只找回一段相似文本。

数据是本机的 `FileSystem_wrh`，1510 个文件。模型是本机 vLLM 上的 Qwen3-8B。下面的「图谱结论」是索引里的事实；「录屏回答」是这次模型实际说出的话。两者不一致的地方，记为中期还没做好的点。

## 1. 重建或确认索引

```bash
bash scripts/index_dataset.sh
```

录屏输出：`seen=1510, indexed=0, unchanged=1510, skipped=0, missing=0`。

| 项目 | 说明 |
| --- | --- |
| 评价维度 | 记忆是否覆盖这次准备的全部文件，以及重复索引时是否还会重做抽取 |
| 已实现 | 按路径、大小和修改时间跳过未改文件。1510 个文件都在库里，没有因为格式被跳过 |
| 未实现 | 这不是增量监听演示。文件保存后多久进入记忆、漏事件后如何补扫，留到期末 |

## 2. 材料属于哪个项目

```bash
python -m pcmemory ask \
  "Attention Is All You Need 这篇论文属于哪个项目？Iris 数据集又在哪个项目？" --no-sync
```

| 项目 | 说明 |
| --- | --- |
| 评价维度 | 项目归属。顶层目录是项目，回答要指出材料在哪一个项目，而不是只引用正文句子 |
| 图谱结论 | Iris 在 `05_Datasets/iris/iris.csv`。论文 PDF 在 `03_Research_Papers/transformers/attention_is_all_you_need.pdf`。`21_Real_GitHub_Projects` 里的教材也讨论这篇论文 |
| 录屏回答 | Iris 属于 `05_datasets`，和图谱一致。论文被答成 `21_real_github_projects` |
| 已实现 | 每个文件有 `BELONGS_TO_PROJECT`，取值是索引根下的第一层目录。Iris 这条已经能答对 |
| 未实现 | 同一主题出现在论文目录和 GitHub 快照时，没有规则指定「原始论文目录优先」。检索先命中快照时，模型会沿用那个项目名 |

## 3. 哪一份最新，更早出现在哪些项目

```bash
python -m pcmemory ask \
  "GPT-2 损失曲线这张图最新的一份在哪个项目，更早在哪些项目出现过？" --no-sync
```

同一张图的字节出现在五个路径。按修改时间从新到旧：

1. `21_Real_GitHub_Projects/nanogpt/nanoGPT-master/assets/gpt2_124M_loss.png`
2. `15_Experiments/runs/baseline/gpt2_training_loss.png`
3. `20_Data_Visualisation/figures/gpt2_loss_curve.png`
4. `08_Media/video/gpt2_loss_curve_poster.png`
5. `01_AI_Projects/transformer_demo/gpt2_training_loss.png`

| 项目 | 说明 |
| --- | --- |
| 评价维度 | 版本与时间；跨项目经历。要同时说出最新位置，以及这份材料以前出现在哪些项目 |
| 录屏回答 | 与上面的顺序一致：最新在 nanoGPT 仓库，更早的副本依次在实验、可视化、媒体海报和 `01_AI_Projects` |
| 已实现 | 相同哈希连成 `SAME_CONTENT`。证据里单独列出「最新一份」和「更早的副本」，并要求模型采用第一项。图片本身不能被 Qwen3-8B 直接看，图谱用的是目录摘要、图像属性和这条时间线 |
| 未实现 | 这五份内容相同，只是观察时间不同，不是五次改写。正文发生变化的 v1 / 最终稿还没有数据，也还没有相应评测 |

## 4. 同一份代码以前在哪个项目写过

```bash
python -m pcmemory ask \
  "nanogpt_model.py 这套模型代码最新出现在哪里，更早在哪个项目里写过？" --no-sync
```

相同字节从新到旧：nanoGPT 仓库的 `model.py`，`15_Experiments/runs/ablation/nanogpt_model.py`，`01_AI_Projects/transformer_demo/nanogpt_model.py`。

| 项目 | 说明 |
| --- | --- |
| 评价维度 | 跨项目、跨时间的代码记忆。问题不是「搜到某段源码」，而是这套实现还在哪些项目里留过副本 |
| 录屏回答 | 最新路径指向 nanoGPT 的 `model.py`，并提到更早的实验项目和 `01_AI_Projects` |
| 已实现 | 与第 3 条同一套内容时间线，对象换成源代码 |
| 未实现 | 没有比较这三份之外、只是文件名相似但内容已经改过的模型文件。函数级的「哪里改过」还没有抽 |

## 5. 音频和视频是否进入同一套记忆

```bash
python -m pcmemory ask \
  "example.ogg 转写了什么，它属于哪个项目？花朵视频又在哪个项目、是什么模态？" --no-sync
```

| 项目 | 说明 |
| --- | --- |
| 评价维度 | 多模态。文本模型不能直接读波形和像素，索引阶段的工具结果要能被项目、模态事实引用 |
| 图谱结论 | `07_Media/audio/example.ogg` 的转写是一条 Wikimedia 示例说明，项目是 `07_Media`。`08_Media/video/flower.mp4` 的模态是 video，项目是 `08_Media`。恐龙吼声 `t_rex_roar.mp3` 没有转写出语音，只保留容器信息 |
| 录屏回答 | 转写被说出，项目 `07_media` 正确。花朵视频的模态 video 正确，但项目被说成 `07_media` |
| 已实现 | 音频经 ffmpeg 和 faster-whisper 写入图谱；视频记录容器、音轨和关键帧。模态有 `HAS_MODALITY` |
| 未实现 | 一条问句里的两个文件仍可能被说成同一个项目。转写有误差，录屏里的 “AgForbus” 应对应 Ogg Vorbis。关键帧没有稳定的画面描述，中期也没有接视觉模型 |

## 对照方式

同一条问题加上 `--no-llm`，终端只打印项目统计、内容时间线和 file id。和「只把检索片段交给同一个 Qwen3」的对照、以及索引和提问耗时，写在 README 的「中期实测」。那次实测里，13 项关系检查图谱方法对上 11 项，纯片段方法对上 0 项；这还不是留出的测试集。
